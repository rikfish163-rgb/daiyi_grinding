# 如何有效向项目甲方汇报工作进展

**文档用途**：规范具身打磨项目组向项目甲方——上海戴屹科技有限公司——进行工作进展汇报的原则、内容与流程，供项目组全体成员执行。

# 一、总体原则：按“黑箱”思路汇报

公司（甲方）只关心系统的**输入与输出**，即“我能提供什么、你能给我什么”；黑箱内部（视觉检测、轨迹规划等算法与设计过程）无需向公司披露。**客户对黑箱内部知道得越少，对我们越有利**——客户正因为不知道怎么做才需要我们，才愿意为方案付费。

1. **输入输出透明**：把“公司需要提供什么、我们交付什么结果”讲清楚，黑箱内部过程不展示。

2. **例外才****报告****中间过程**：仅当涉及**新增****设备投入**（如摄像头精度不够、需要更换更高精度设备）或**需求变更**时，才与公司讨论中间过程，论证必要性。

3. **项目性质认知**：本项目委托学校验证技术可行性、探讨突破极限，因此汇报要让公司看到“投入换结果”的进展与价值，而不是纠结于内部技术细节。

4. **正面回应客户关心的三件事**：①技术指标能否达到；②甲方需提供什么设备、投入多少成本；③项目时间节点（什么时候完成什么）。每次对外汇报都应有明确回应。

# 二、汇报内容：三类核心信息

对外汇报只同步三类内容，其余一律不展示：

1. **输入需求**：公司需要提供什么

    - 如约 500 个具备不同毛边、残根特征的铸件样本，或已采集的点云数据；

    - 如更高精度的摄像头、更多测试件、机械臂等设备资源；

    - 输入界面（输入需求）必须向公司讲清楚。

2. **输出结果**：当前做到什么程度

    - 现有指标哪些已经达到、哪些尚未达到；

    - 下一步优先达到什么、后达到什么；

    - 输出指标与公司目标的差距。

    - 关键节点与完成时间：什么时候完成什么，与公司预期对齐。

3. **资源诉求**：需要公司支持什么

    - 新增投资（设备升级、扩容）、数据、人员配合等；

    - 报告资源需求时提供“投入多少、得到什么结果”的对应关系。

4. **对外介绍研究方法与成果的讲法**：对外需要介绍算法或论文成果时，按客户能听懂的逻辑讲，不展开技术细节：

    - 方法是什么、大致流程如何、与我们的项目有什么关系；

    - 若采用该方法，需要多少样本、样本由谁采集（客户提供还是我们采集）、人工标注与投入成本多少；

    - 比较多种候选方法后自选 3 种，向客户讲“我们下一步要试这 3 种方法”，并给出初步优劣判断（如 Transformer 类效果更好但计算量大），优势尽量用百分比量化表达。

# 三、会议机制：内部会与公司汇报会拆分

1. **项目组****内部会**：充分研讨技术细节——要实现系统，必须深入讨论具体技术问题；会前由学生做好汇报准备。

2. **公司汇报会**：控制在**半小时左右**，只谈公司感兴趣的内容：

    - ① 团队有无新的要求、公司能提供什么新东西；

    - ② 对需求、指标的理解问题；

    - ③ 现有指标达成情况与优先级（先达到什么、后达到什么）。

3. **时间安排**：周二 10:00–11:00 内部会（每人汇报控制在10分钟以内）；11:00–11:30 邀请公司做约半小时同步汇报。

4. **参会范围**：公司汇报会由项目负责人协调、指定主讲学生汇报；公司人员无需全程参加内部会，避免浪费双方时间。

# 四、汇报准备流程

1. **材料筛选**：学生汇报内容提前筛选，不用 AI 生成的无价值报告在会上朗读；

2. **内容核对**：确认汇报覆盖“输入需求、输出结果、资源诉求”三类信息，且输入界面描述清楚；

3. **事项确认**：提前列出需要公司拍板的事项（如数据需求、人造样本方案、设备投资），会上逐条确认；

4. **节奏演练**：公司汇报会汇报总时长控制在半小时内，重点讲进展与需求，不展开技术细节。

5. **执行摘要前置**：每份对外汇报文档开头放一页执行摘要（executive summary），5 分钟内讲清本次的输入需求、输出结果、资源诉求及与项目的关联，后附技术细节——一份文档同时适配内部会与公司汇报会。

# 五、典型汇报话术示例

- **开场**：“本次汇报向公司同步三件事：输入需求、当前结果、需要公司支持的资源。”

- **输入需求**：“算法训练需要约 500 个具备不同毛边、残根特征的铸件样本（或点云数据），我们会提供采集方法，请公司确认能否提供、以什么形式提供。”

- **输出结果**：“当前指标 A 已达到、指标 B 未达到；下一步优先完成指标 B，预计时间节点为 XX。”

- **资源诉求**：“现有摄像头的精度与视野范围难以覆盖铸件尺寸范围，需要评估更高精度方案，涉及新增投入\*\*\*资源，请公司考虑。”

- **收尾**：“请公司确认以上输入需求与资源诉求，我们将在下轮汇报前完成 XX。”

# 六、注意事项

1. **指标定义可适当抬高、预留迭代空间**：定义低了，项目做完公司不再续约；定义高一点、暂时达不到，后续还可谈追加投入。

2. **人造（合成）样本必须公司确认**：若公司无法提供足量符合要求的样本，可提出人造样本方案，但必须取得公司**正式同意**后方可纳入训练集——系统输入最终属于公司，不能未经同意自行造数据。

3. **需求必须主动提出**：公司对算法不了解也不感兴趣，团队必须主动提出明确要求（样本数量、缺陷类型、数据形式）并提供采集方法，公司据此组织资源；提不出要求，后面会因缺数据无法训练。

4. **公司汇报****指导原则**：项目组与公司谈中间过程只发生在“需要更多资源”（摄像头精度或速度不够、需升级设备）时；平时按黑箱原则只谈输入、输出、资源。

5. **汇报纪律**：学生汇报提前筛选内容，不在会上朗读 AI 报告；每个学生的汇报时间控制在 10 分钟，避免时间浪费。

6. **需求条目化、厂商资料由公司出面索取**：对公司的需求要逐条列明（第一点需要哪些报告或资料，第二点需要多少种零件与样本）；若需索取厂商内部资料（如 3D 相机厂商的打磨场景路径规划算法文档），由公司（付费方）出面联系索取，学生直接索要对方不会配合。
