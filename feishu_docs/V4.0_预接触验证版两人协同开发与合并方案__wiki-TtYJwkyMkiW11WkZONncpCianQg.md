# V4\.0 预接触验证版两人协同开发与合并方案





共同基线：`scan_n_plan_precontact` V4\.0。分工原则是“感知与工艺规划”和“机器人运动与执行验证”相互独立，通过冻结的数据契约合并。两人中指定一名**系统集成负责人**，负责接口冻结、分支合并、回归测试和最终证据归档；这不是第三个开发岗位，而是合并责任。



## 一、当前基线



已具备 ROS 2 Humble、MoveIt 2、UR5e、公开点云、局部表面重建、Noether 路径、URDF/FK/Jacobian/碰撞/时间参数检查、RViz 回放和 `burr-defect/v1` 接口预留。



尚未完成真实毛刺识别、真实坐标标定、局部缺陷路径的完整 MoveIt 联调、局部轨迹假控制器执行、接触力和材料去除模型。V4\.0 原始目录只读保存，开发使用复制目录或 Git 分支。



|角色|负责方向|主要产出|
|---|---|---|
|A：检测结果适配与工艺规划|接收外部检测结果、表面、法向、加工策略、复扫接口|检测结果校验、局部路径、工艺参数、复扫决策|
|B：机器人与仿真验证|URDF、工具模型、IK、MoveIt、碰撞、时间化、假控制器|关节轨迹、验证报告、执行反馈、交接门禁|



系统集成负责人必须在每次合并前检查：schema 版本、坐标系、单位、源数据哈希、计划哈希、轨迹哈希、测试结果和 `simulation_only` 标志。任何一项缺失都不能合并到集成分支。



## 二、任务 A：检测结果适配、几何与工艺路径



### 目标



接收外部点云物体/毛刺检测模块输出的缺陷结果，将其转换为带坐标、法向和工艺参数的局部加工计划，并支持复扫后的补磨决策。本任务不开发物体检测或毛刺识别模型。



### 工作包



|编号|工作内容|验收标准|
|---|---|---|
|A1|校验外部检测接口|校验 schema、单位、坐标系、时间、置信度和来源哈希；不负责检测精度|
|A2|检测结果坐标与表面几何适配|将外部缺陷结果映射到工件/`base_link`，异常结果拒绝|
|A3|缺陷区域转局部几何路径|根据检测区域和表面模型生成局部栅格/中心线路径|
|A4|生成进刀、加工、退刀、转场阶段|刀次、间隙、进给和阶段标签显式记录|
|A5|复扫结果适配与补磨决策接口|接收外部复扫结果，区分合格、补磨、最大轮次和改善不足|
|A6|建立接口和几何负例|空结果、错误单位、坐标错误、缺少法向、越界区域可重复拒绝|



### 负责文件



```Plain Text

local_defect_planner.py
defect_interface.py
defect_result.json
local_defect_plans.json
closed_loop_report.json
```



### 输出给 B 的接口



文件：`local_defect_plans.json`。约定 `schema=local-grinding-plans/v1`、`frame=base_link`、`units=m`，每个 segment 包含 `defect_id`、`segment_id`、`strategy`、`phase`、`waypoints`、`normals`、`passes`、`feed_mm_s` 和 `clearance_m`，并记录 `run_id`、外部检测结果哈希、源表面数据哈希和计划生成时间。



waypoint 是名义表面点；预接触偏置由 B 根据共享工具配置只应用一次。A 不输出关节角、不调用控制器，也不把模拟去除结果写成真实去除率。A 负责外部检测结果适配和工艺目标，B 负责把工艺目标变成机器人轨迹；双方不得重复解释 `waypoint`、`passes` 和 `clearance_m`。



## 三、任务 B：六轴运动、仿真与安全验证



### 目标



将 A 的局部计划转换为可验证的 UR5e 关节轨迹，完成 MoveIt 碰撞验证、时间参数化、假控制器执行和反馈回传。



### 工作包



|编号|工作内容|验收标准|
|---|---|---|
|B1|修复 ROS 服务和导入问题|`GetParameters` 使用正确服务包；容器内 import 通过|
|B2|统一工具几何和坐标变换|砂轮、主轴、TCP、tool0 偏置只配置一次|
|B3|建立机器人、工具、工件、夹具和工作台碰撞场景|有意碰撞负例被拒绝|
|B4|调用 IK、笛卡尔路径和状态有效性服务|每个局部段的 IK、fraction、中点和状态检查通过|
|B5|加密碰撞、关节限位、FK、Jacobian 验证|输出完整阈值和采样范围|
|B6|完成进刀/加工/退刀/转场时间化|阶段、目标速度和实际速度可追踪|
|B7|修复轨迹交接门禁|统一 `trajectory_sha256`；成功、缺文件、篡改和非仿真案例均通过测试|
|B8|接入 GenericSystem 假控制器|有反馈进度、阶段、速度、取消和恢复；不发送真机命令|
|B9|返回已执行段和失败原因|未执行区域不会触发 A 的去除模型|

### 输出给 A 的接口



文件：`local_execution_result.json`。至少包含 `run_id`、计划和轨迹哈希、`simulation_only`、`status`、`completed_segments`、取消段、错误码和反馈时间。只有成功且明确完成的 segment 才能用于复扫去除模型。



工具基线为轮缘局部点 `[0,0.055,0.150] m`、名义间隙 8 mm。主轴中心 70 mm 与砂轮中心 150 mm 不得混淆；企业工具到位后必须用实测配置替换。



### 加工语义必须显式化



`passes` 不得只作为数量字段。每一刀应展开为 `pass_id`、`offset_m`、`feed_mm_s`、`spindle_rpm`、`phase_sequence` 和 `recovery_policy`。每个路径点必须明确属于 `approach`、`process`、`retract` 或 `transfer`。如果 B 因关节限制降低速度，必须记录目标速度、实际速度和降速原因。



## 四、共同接口规则



1. 坐标单位统一为米，速度使用 `mm/s`，角度使用 `rad`。

2. 所有点云、计划、轨迹和报告绑定 `run_id`、源数据哈希、坐标系和生成时间。

3. `frame` 必须明确；联调默认使用 `base_link`。

4. `passes` 必须在 B 的轨迹中实际展开，不能只存为元数据。

5. 工具偏置只能由 B 应用一次。

6. 外部模块负责物体/毛刺检测；A 负责检测结果适配和路径，B 负责机器人轨迹和执行；跨边界修改必须同步更新契约测试。

7. V4\.0 原始目录和历史结果不覆盖，新结果写入独立 run 目录。

    

## 五、合并顺序



### 阶段 1：接口冻结



A、B 用一个缺陷、一个加工段和一组进刀/加工/退刀数据确认 JSON 字段、坐标和偏置语义，契约测试通过后再并行开发。



### 阶段 2：单段联调



A 生成一个局部段；B 完成 IK、笛卡尔路径、碰撞和假控制器执行；共同核对 run\_id、计划哈希、segment\_id 和反馈范围。



### 阶段 3：多段多刀



增加多个缺陷和多刀执行，检查转场、阶段标签、速度限制、取消和恢复。



### 阶段 4：闭环合并



B 将实际完成段返回 A；A 根据已执行范围更新复扫结果并决定补磨或停止；B 再验证补磨轨迹。最终报告必须区分离线算法、MoveIt 验证和假控制器执行结果。



### 阶段 5：统一回归



集成负责人使用固定测试集运行完整链路：平面、斜面、曲面、多缺陷、小缺陷、噪声、遮挡和不可达区域。每次合并必须比较检测结果、路径覆盖、规划结果和执行反馈；不允许只以“脚本退出码为 0”作为通过标准。



## 六、统一测试与验收指标



|类别|必须记录的指标|
|---|---|
|外部检测接口|schema、单位、坐标系、置信度、时间戳和结果哈希；本项目不评估 precision/recall|
|几何|点云配准误差、表面重建误差、法向误差、路径覆盖率|
|运动|IK 成功率、MoveIt fraction、关节限位裕量、Jacobian 指标|
|碰撞|原始点、中点、加密点、工具/工件/夹具分别通过情况|
|工艺|目标与实际 TCP 速度、阶段时间、刀次、路径长度|
|闭环|残余峰值、补磨次数、停止原因、已执行区域比例|
|工程|规划耗时、反馈延迟、哈希一致性、失败恢复时间|



物体/毛刺检测由外部模块负责。本项目只验证检测结果能否被正确接收、坐标转换、生成路径并进入机器人规划，不能据此评价外部检测模型的 precision/recall 或真实去除率。



## 七、故障注入与真机隔离门禁



集成负责人必须安排以下负例：IK 无解、工件碰撞、夹具碰撞、单位错误、坐标系错误、空点云、哈希篡改、反馈中断、控制器取消和规划超时。每个负例必须明确是拒绝规划、暂停、取消、回安全位还是等待人工确认。



真机前置资料单独建立清单：厂商 URDF/SRDF、真实工具和 TCP、手眼标定、工件/夹具碰撞模型、控制柜驱动、急停、限速、低速空跑和无接触测试。仿真验收通过不能自动打开真实控制器；所有当前输出继续保持 `simulation_only=true`。



## 八、最终验收



- 同一 run\_id 的点云、缺陷、计划、轨迹和执行报告可串联；

- 至少一个缺陷段真实进入 MoveIt 和假控制器，并正确回传执行范围；

- IK 失败、碰撞、哈希错误、反馈中断和取消不会被记为加工成功；

- RViz 可区分进刀、加工、退刀和转场；

- 局部轨迹经过第二次碰撞检查和时间参数化；

- 复扫停止原因区分合格、最大轮次和改善不足；

- 全流程保持 `simulation_only=true`，不接真实控制柜；

- 新结果独立归档，保留 V4\.0 原始快照。

    

## 九、专家评估



A 不能用“收到检测结果”替代可执行路径，B 不能用“MoveIt 通过”替代真实去除效果。合并必须以同一份外部检测结果、同一坐标系、同一计划哈希和同一执行反馈建立证据链。完成以上验收前，项目仍是仿真级局部闭环，不具备直接部署真机的条件。
